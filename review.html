结论

原稿不适合原样发布：新增反例确实暴露了执行边界与评分器漏洞。本轮已修复已复现的问题，修订技术表述与引用，并重新生成交付物。修订版可作为自学教材与教学实验发布；不能据此声称代码已经具备生产资金操作能力，或已经完成真实模型、MCP、微调的端到端验收。

本次是对当前稿件的逐章编辑与技术复核，不是独立专家同行评审，也不构成“全书绝无错误”的保证。没有用字数、页数或测试数量替代内容判断。

编号 问题与影响 修订与证据

R02 已确认布尔值没有绑定订单，字符串 false 也可能被当成真 执行器绑定订单与批准金额；存储层要求真正布尔值。第二笔订单、金额变化、错误类型均有测试；确认过期与撤销仍未实现
R03 评分器漏查退款状态、订单缺失与账本余额不一致，可能误判通过 增加退款状态、订单完整性、累计金额对账；篡改反例由通过变成失败。正文评分示例也改为检查全部新增记录，避免先过滤掉错误对象
R04 对比只校验任务 ID 和固定数据集名称，同 ID 改题或重复 ID 可能被漏掉 增加任务内容 SHA-256、评分器版本与 ID 唯一性检查；旧报告必须重跑
R05 最终回答轮的 usage 没被记录，轨迹缺少调用参数 所有模型轮次记录 usage，补充工具调用事件和参数；最终轮和重放轮均有验证
R06 API 适配器默认允许重定向，并只排除少数异常结束原因 禁止认证请求重定向；明确允许的结束原因及消息组合；使用离线 HTTP 响应夹具验证，不声称接通外部模型
R07 API、缓存章节以岗位/架构文章作间接引用；稳定前缀容易被理解成必然命中 补入直接技术文档；解释缓存边界、适用条件与计费桶；固定 MCP 文档版本；两条岗位页面本轮 403 明确披露
R08 pass@k、置信区间、RL 范围与保留测试集流程有易误解之处 补独立性与候选选择器条件、区分单侧零事件上界和双侧区间、限定在线 RL 讨论、冻结后再比较保留集
R09 部分练习要求新增实验包已经包含的任务；第 22 章标题容易让人误以为是真实线上案例 改为第 7/8 天和剩余 1 分的边界练习；改为“可复现的失败分析”，保留合成环境标记
R10 浏览器保存记录中字段类型异常可能使阅读器初始化失败 恢复时逐字段校验，保留合法笔记；浏览器实际检查异常状态恢复与导入导出

首次运行新增的 15 个检查时，12 个失败、1 个异常、2 个数值梯度检查通过。修复后再补充批准金额、同 ID 重放和正常 API 响应检查，最终全套 43 项 Python 测试通过。这些数量包含不同反例，不代表 13 个彼此独立的生产事故。
